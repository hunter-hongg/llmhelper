## Problem Statement

The `usage` subcommand presents a single snapshot of token consumption and activity at a point in time. When a user runs `usage --last 7d` today and again next week, they can see two totals but have no tool to compute the delta between them: which Sources, Projects, or Models grew, which shrank, which appeared or disappeared. The user is left to eyeball two separate outputs or export to a spreadsheet. There is no way to answer the question "what changed?" without leaving the CLI.

## Solution

A second subcommand `diff` on `llmhelper` that:

1. Loads Sessions from all configured Sources (Claude Code, OpenCode, OMP) using the same `Source` registry as `usage`.
2. Applies the user's `--last <duration>` and `--prev <duration>` flags to define two sliding time windows relative to `now`: the **current window** (`[now - last, now]`) and the **previous window** (`[now - prev - last, now - last]`).
3. Runs `usage`'s existing filter + aggregation pipeline independently on each window, producing two sets of aggregated Groups by the user's chosen `--group-by` dimension (Source / Project / Model).
4. Computes a delta for every Group key that appears in either window, outputting absolute value change, percentage change, and a presence flag indicating whether the Group is `both`, `new` (curr only), or `removed` (prev only).
5. Renders the result as a terminal table (default), `--json`, or `--csv`. No TUI, no live refresh — `diff` is a one-shot comparison operation.

## User Stories

1. As an agent user, I want to compare my token consumption between two time windows, so that I can see whether my Usage is trending up or down.
2. As an agent user, I want to see the absolute token delta per Source, so that I can identify which Source drove the change.
3. As an agent user, I want to see the absolute token delta per Project, so that I can tell which repository is consuming more tokens.
4. As an agent user, I want to see the absolute token delta per Model, so that I can see whether a model switch reduced token spend.
5. As an agent user, I want percentage change alongside absolute change, so that I can understand relative magnitude.
6. As an agent user, I want Groups that appeared only in the current window flagged as "new", so that I can spot unexpected new activity.
7. As an agent user, I want Groups that appeared only in the previous window flagged as "removed", so that I can spot activity that stopped.
8. As an agent user, I want a compact terminal table output, so that I can read the comparison directly without opening a file.
9. As a script author, I want `--json` output, so that I can pipe the comparison into other tools.
10. As a script author, I want `--csv` output, so that I can import the comparison into a spreadsheet.
11. As a power user, I want `--last` and `--prev` to accept the same duration format as `usage` (e.g. `7d`, `24h`), so that I am familiar with the syntax.
12. As a power user, I want `--last` and `--prev` to support different durations (e.g. `--last 1d --prev 7d`), so that I can compare a short window to a longer baseline.
13. As a power user, I want `--source` to filter the comparison to a single Source, so that I can isolate changes in one agent.
14. As a power user, I want `--project` and `--model` filters to narrow the comparison to a subset, so that I can focus on a specific area.
15. As a power user, I want `--group-by source|project|model` to control the grouping dimension of the delta, so that I can answer different questions.
16. As a multi-machine user, I want `--claude-dir`, `--opencode-db`, and `--omp-dir` overrides on `diff`, so that it works on machines with non-default paths.
17. As a config-driven user, I want `diff` to respect `~/.config/llmhelper/config.toml`, so that my source path defaults are shared with `usage`.
18. As a user, I want the comparison to degrade gracefully when a Source is absent in one window, so that partial data does not produce an error.
19. As a user, I want the comparison to show session count delta and message count delta alongside token delta, so that I understand whether more sessions or longer sessions drove the change.
20. As a user, I want Groups where the previous window had zero tokens to display percentage as a special indicator rather than a division error, so that the output stays clean.
21. As a user, I want cost delta shown only within a single Source, so that I do not see a misleading cross-Source cost sum.
22. As a user, I want the tool to error clearly when `--last` or `--prev` contains an invalid duration string, so that I can correct my input quickly.
23. As a user, I want `--last` and `--prev` to be required, so that running `diff` without them gives an actionable error rather than an empty comparison.
24. As a user, I want `--json` and `--csv` to be mutually exclusive, so that the output format is unambiguous.

## Implementation Decisions

### CLI shape

```
llmhelper diff --last <duration> --prev <duration>
    [--group-by source|project|model]
    [--source claude|opencode|omp]
    [--project <substring>]
    [--model <substring>]
    [--json|--csv]
```

- `--last` and `--prev` are **required** positional flags. Missing either prints a Clap error and exits non-zero.
- `--last` and `--prev` accept the same `Nd`, `Nh`, `Nm` format as `usage --last`. Parsing logic is shared.
- `--group-by` defaults to `source` (same default as `usage`).
- `--json` and `--csv` are mutually exclusive; both set → error.
- `--last` / `--prev` are independent of each other — they define two durations, not a window pair. This lets `--last 1d --prev 7d` compare a single day to a week-long baseline.

### Window construction

- **Current window**: `[now - last, now]` (right-inclusive on `now`).
- **Previous window**: `[now - last - prev, now - last]` (right-exclusive on `now - last` to avoid overlap).
- Both windows use `--since` under the hood via the existing `Filter` type. No new filter semantics are needed.
- Example: `--last 7d --prev 7d` → current = [now-7d, now], previous = [now-14d, now-7d].

### Diff computation

For each Group key present in either window, produce a `DiffRow` with:

| Field | Type | Description |
|---|---|---|
| `key` | String | The group key (source name, project path, or model id) |
| `presence` | Enum | `"both"`, `"new"`, or `"removed"` |
| `prev` | Option<Snapshot> | The previous window's snapshot, `None` when `presence = "new"` |
| `curr` | Option<Snapshot> | The current window's snapshot, `None` when `presence = "removed"` |
| `delta` | Delta | Absolute difference computed as `curr - prev` |

A `Snapshot` contains the same fields as a `usage` Group: sessions, messages, token breakdown, optional cost.

`Delta` contains:

| Field | Type | Description |
|---|---|---|
| `sessions` | i64 | `curr.sessions - prev.sessions` (signed) |
| `messages` | i64 | `curr.messages - prev.messages` (signed) |
| `tokens` | TokenBreakdownDelta | Signed delta per token field |
| `cost` | Option<f64> | `curr.cost - prev.cost`, only when both are `Some` and from the same Source |
| `pct` | Option<TokenBreakdownPct> | Percentage change per token field, `None` when prev is zero |

### Cost handling (follows ADR-0001)

Cost delta is **only** computed when both windows' cost values are present **and** the Group's Source is single-valued (not mixed). If the Group crosses Sources or either window has `cost = None`, the `delta.cost` field is `None`. This mirrors the existing mixed-source cost behavior in the aggregator and preserves the ADR-0001 constraint that cost must never be summed across Sources.

### Percentage computation

- `pct = ((curr - prev) / prev) * 100`, rounded to one decimal place.
- When `prev = 0` for all token fields: `pct = None` (displayed as `N/A` or omitted in JSON).
- When only some fields are zero: that field's percentage is `None`, others are computed normally.

### Output formats

**Terminal TUI** (default — interactive, refreshes on `r`/Tab/timer):

Two-level band-header layout (band row: `prev` / `curr` / `Δ` / `Δ%`; name row: `st in out in out in out in out sess msgs cost`).
Columns in order:

| Key | st | prev in | prev out | curr in | curr out | Δ in | Δ out | Δ% in | Δ% out | sessions Δ | messages Δ | cost Δ |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

- `st` = status: `✓` both windows, `+` new (curr only), `−` removed (prev only).
- Token counts use the same magnitude formatting as `usage` (raw below 1K, then K, M, B).
- `presence = "new"` rows render `prev` cells as `—`; `presence = "removed"` rows render `curr` cells as `—`.
- Cost column shows `n/a` when not computable (mixed-source or missing cost in one window).
- Percentage when prev = 0 shows `n/a`.
- Cache fields (`cache_read`, `cache_write`) and their percentages are **omitted from the TUI table**; they remain in `--json` and `--csv`.
- Header line shows current grouping dimension, total rows, and a session summary (`sessions X → Y  Δ ±N`).
- Footer shows a legend for `st` symbols and Δ color semantics, plus key bindings.
- On narrow terminals (<110 cols), the `Δ%` columns are hidden to keep all other columns visible.
- Delta cells are colored by sign: green = positive (up), red = negative (down), grey = zero. This applies consistently to every Δ column.
- The selected row is indicated by an underlined key (no prefix characters to avoid per-frame horizontal jitter).

**`--json`** (mirrors the `usage --json` structure):

```json
{
  "windows": {
    "current": {"since": "...", "until": "..."},
    "previous": {"since": "...", "until": "..."}
  },
  "group_by": "source",
  "rows": [
    {
      "key": "claude",
      "presence": "both",
      "prev": { "sessions": 10, "messages": 60, "tokens": { ... }, "cost": null },
      "curr": { "sessions": 14, "messages": 88, "tokens": { ... }, "cost": null },
      "delta": { "sessions": 4, "messages": 28, "tokens": { ... }, "cost": null, "pct": { ... } }
    }
  ]
}
```

**`--csv`**:

One row per Group key. Columns: `group_key, presence, prev_sessions, curr_sessions, delta_sessions, prev_messages, curr_messages, delta_messages, prev_input, curr_input, delta_input, delta_pct_input, prev_output, curr_output, delta_output, delta_pct_output, prev_cache_read, curr_cache_read, delta_cache_read, prev_cache_write, curr_cache_write, delta_cache_write, prev_cost, curr_cost, delta_cost`.

### Modules built or modified

- **New `DiffArgs` struct** in the CLI module: holds `last`, `prev`, plus shared filter flags (`--group-by`, `--source`, `--project`, `--model`, `--json`, `--csv`).
- **New `Command::Diff(DiffArgs)` variant** in the CLI enum.
- **New diff domain module**: `DiffRow`, `Snapshot`, `Delta`, `TokenBreakdownDelta`, `TokenBreakdownPct`, `Presence` enum, and the `compute_diff` function that takes two `AggregateResult` values and produces a `Vec<DiffRow>`.
- **New `DiffRenderer` methods** on the output module: terminal table rendering, JSON serialization, CSV serialization.
- **New `run_diff` function** in `main.rs`: loads Sources, builds two Filters, runs `AggregateResult::from_records` twice, calls `compute_diff`, renders output.
- **`Filter` extension**: add a `since`-and-`until` constructor (or `within(start, end)`) so the previous window can express an upper bound without reusing `--last` semantics. This is the only change to the existing filter.

### Architectural decisions

- `diff` defaults to an interactive TUI that loads data once per window and renders the comparison; `--json` and `--csv` produce one-shot output without a TUI.
- Background tokio task recomputes both windows at a configurable refresh interval (from config). Window boundaries are recomputed on each refresh from the stored `--last` / `--prev` durations so the header timestamps stay honest even while the TUI remains open.
- The `Source` trait, registry, `Record`, `AggregateResult`, and `Filter` types are reused verbatim from `usage`. No new Source implementations, no new trait methods.
- `compute_diff` takes two already-computed `AggregateResult` values — it does not take raw `Record` lists. This keeps the diff logic independent of loading/filtering and testable in isolation if needed.
- Group keys are matched by exact string equality (same grouping dimension on both sides). No fuzzy matching.
- `diff` never modifies the Source data or writes any files.

### Error handling

| Scenario | Behavior |
|---|---|
| `--last` or `--prev` missing | Clap error, exit 1 |
| Invalid duration string | `anyhow` error with context ("invalid --last duration '7x'"), exit 1 |
| `--json` and `--csv` both set | Validation error, exit 1 |
| Previous window has zero records (all `presence = "new"`) | Renders normally, no error |
| Source directory does not exist | Degrades with `SourceStatus` error, same as `usage` |

## Testing Decisions

### Seam

**Single `--json` CLI seam**, driven by the real binary against existing fixture directories — identical to the seam already used by `usage` integration tests. No new seam, no TUI testing.

### Fixture strategy

Reuse the existing `tests/fixtures/` layout (`claude/`, `opencode/`, `omp/`). Fixture records already carry `started_at` timestamps. To produce two distinct windows, tests pass `--last` and `--prev` durations that partition the fixture timestamps into prev and curr halves. No new fixture files are needed.

### What makes a good test

Only external behavior is asserted: given known fixture data and specific `--last`/`--prev` durations, the emitted JSON structure, field values, and error codes match expectations. No tests inspect internal types (`DiffRow`, `Delta`, etc.) directly.

### Test coverage (integration tests)

| Scenario | What it asserts |
|---|---|
| **Both windows have data, delta is positive** | `delta.tokens.input > 0`, `presence = "both"` |
| **Both windows have data, delta is negative** | `delta.tokens.input < 0`, `presence = "both"` |
| **Group only in current window** | `presence = "new"`, `prev` is `null` |
| **Group only in previous window** | `presence = "removed"`, `curr` is `null` |
| **`--source` filter** | Only that Source's Groups appear in diff rows |
| **`--group-by` changes grouping** | Group keys match the selected dimension |
| **Cost cross-source not summed** | Mixed-Source Group's `delta.cost = null`, consistent with ADR-0001 |
| **Percentage when prev = 0** | `delta.pct` is `null` for the affected fields |
| **Invalid `--last` / `--prev` duration** | CLI exits non-zero with error message |
| **`--json` and `--csv` mutually exclusive** | CLI exits non-zero |
| **Missing `--prev`** | CLI exits non-zero |
| **CSV output structure** | Header row contains diff-specific columns |
| **Zero records in one window** | CLI exits 0, rows all marked `new` or `removed` |

### Prior art

All tests mirror the existing `usage` integration test style in `tests/integration.rs`: invoke the binary with `--json`, parse the result with `serde_json`, assert on field values. No unit tests for internal diff types are needed in v0.2 — the CLI seam covers them.

## Out of Scope

- **Window alignment to calendar boundaries** (e.g. Monday-to-Monday): shipped
  separately in spec [0017](0017-diff-calendar.md) via `--calendar`; this spec
  keeps sliding windows as the default.
- **Historical diff** (comparing arbitrary past dates, not sliding windows from now): out of scope; `--since` alone does not provide a pair of windows.
- **Diff by date** (day-by-day time series): out of scope; a single prev-vs-curr comparison only.
- **Statistical significance / anomaly detection**: raw delta only, no statistical overlay.
- **Cost aggregation across Sources**: explicitly forbidden by ADR-0001, as in `usage`.
- **Diff between two non-temporal filters** (e.g. diff by `--project A` vs `--project B`): temporal windows only.
- **Any subcommand beyond `diff` for v0.2**.

## Further Notes

- The `Filter` type currently supports `--since` (lower bound) and `--last` (lower bound from now). For the previous window, an upper bound is needed. The cleanest approach is to add an optional `until: Option<DateTime<Utc>>` field to `Filter` and a `within(since, until)` constructor. The existing `--last` behavior is preserved (it sets `last` which is resolved to a `since` at evaluation time); the new `until` is independent and only used by `diff`.
- `DiffRenderer` shares the magnitude formatting helper used by `usage` output — the K/M/B formatting should be extracted to a shared utility if it is currently inline.
- The `compute_diff` function can be unit-tested independently if desired, but the single CLI seam is the canonical test path per project convention.
- `diff` intentionally does not share state with `usage` (no `Arc<RwLock>`, no background task). It is a simpler command by design.
