# Man pages and completions are generated at run time, not at build time

Spec 0028's contract for discoverability is simple to state and hard to
keep: the man pages and shell completions must be derived from the *live*
`Cli` tree, because a checked-in page drifts the first time a flag is added,
and the drift is invisible — a stale man page is worse than none, because a
user trusts it. The spec's own draft said `build.rs` would do the
generating. It cannot, for a measured reason: `src/cli.rs` carries 33
`crate::` references (its argument types reach into `crate::filter`,
`crate::config`, and the rest of the library), so a build script cannot
`include!` the CLI definitions — it would have to depend on the crate it
builds, and a `build.rs` that links the crate-under-build is a circular
dependency cargo will not run.

The decision is therefore: the generator ships **in** the binary. A hidden
`llmhelper man` subcommand renders, from the in-memory `Cli` tree of the
running binary, one roff page per subcommand via `clap_mangen` and one
completion script each for bash, zsh, fish, and PowerShell via
`clap_complete`, into `target/dist` by default (`--out-dir`, `--stdout`,
and `--completions <shell>` for one script on stdout, for packaging).
`src/dist.rs` is the whole implementation: no build script, no checked-in
artifact, no second copy of the CLI definition.

The alternative was checked-in artifacts regenerated by a maintainer. That
restores the drift the spec exists to make unrepresentable, and puts the
regeneration burden on the one human who should not have to think about it.

Accepted costs, named rather than hidden: `clap_complete` and `clap_mangen`
are runtime dependencies, not build-dependencies, so they land in the
installed binary's code surface (a few hundred KB of roff/generator code a
user never invokes); and a user who wants the page must run the binary once
rather than finding the page pre-shipped with the crate. The first is
cheaper than a build-dependency cycle that does not exist; the second is the
shape of the only viable design — the user who wants a man page is the user
who already installed the binary.

`build.rs` is not resurrected later by refactoring `cli.rs` into a
dependency-free leaf: doing so would mean restructuring the CLI module to
serve a build script, which optimizes a hypothetical (regeneration by a
build script) over the actual contract (no drift), and the `man` subcommand
keeps that contract at zero build-time cost.
